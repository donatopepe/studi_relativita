# UMCH engineering loop with hypothesis reformulation gate

## Authorization

Autonomous study may continue beyond bounded corrections. If a documented dead end is reached, initial/current hypotheses may be reformulated using accumulated negative results and operator-valued experience.

## Dead-end criteria

A reformulation candidate is allowed only when all apply:

- current route has explicit scoped statement and dependencies;
- strongest counterexample/identifiability analysis has been run;
- no bounded correction resolves blocker;
- blocker is structural, not merely missing computation;
- alternatives and discarded paths are recorded;
- history remains preserved.

## Reformulation protocol

1. Freeze old hypothesis as `SUPERSEDED_AS_CORE` or scoped historical status; never rewrite it silently.
2. Create new spec with change ledger: retained, removed, added assumptions; changed domain/object/falsifier; compatibility with prior results.
3. Re-run null controls, dimensions, frame/domain/dependence, identifiability and inference gates.
4. Update bilingual authoritative paper only after explicit human ratification.
5. Do not auto-merge hypothesis-contract changes. Open PR labeled gate and stop loop pending human decision.
6. Conservative tests/audits use isolated worktree/branch and may auto-merge with green CI.

## Current priority

Derive nonradial operator response from finite windows/transport/boundaries/cross-channel maps in exact geometries. Test counterexamples first. Scalar q branch remains secondary.

## Safety

Never invent theory, source, data, ell0, detection, or mechanism. A reformulation may weaken/replace claim, not manufacture support. Core stays `UNPROVEN` until independent evidence.
